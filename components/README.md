# components/

The **UI primitive registry** plus runtime implementations. The catalog is what gives Atelier coverage: a small, well-designed set of ~56 primitives covers 90% of web app patterns. The compiler picks from this catalog; the runtime renders it. Free-form HTML generation is explicitly out of scope.

## Files

- `registry.json` — the catalog (props schemas, data sources, supported actions, design tokens, examples). Generated from [`@atelier/components`](../packages/components/src/registry.ts) via `pnpm components:sync`.
- `composition-rules.json` — sibling map of `ComponentId -> CompositionRule`, also generated by the same sync. Each rule declares whether the component accepts wildcard children (`'*'`), no children at all (`'leaf'`), or an explicit allow-list. The compiler reads this to produce valid manifest layouts; the runtime can validate at render time.
- `examples/{name}.json` — one or more usage examples per component, used by the compiler as in-context guidance.
- Implementations live in [`@atelier/components`](../packages/components/README.md).
- **Naming**: PascalCase component names (`TaskQueue`, `DecisionQueue`, `ThreadView`).

### Extending the rules

To add or change a composition rule, edit `COMPOSITION_RULES` in [`packages/components/src/registry.ts`](../packages/components/src/registry.ts) and run `pnpm components:sync`. The script regenerates BOTH `registry.json` and `composition-rules.json` and refuses to emit invalid output (it parses through `CompositionRulesSchema` from `@atelier/schemas`). `pnpm components:check` is the CI gate — it fails on any drift between the code-side rules and the on-disk JSON.

## Adding a component

Follow [`../AGENTS.md`](../AGENTS.md) — section "When asked to add a component":

1. Add the props schema to `/components/registry.json`.
2. Implement the component in the runtime SDK.
3. Add usage examples at `/components/examples/{name}.json`.
4. Document allowed `data_sources` and `actions_supported`.
5. Add accessibility tests.
6. Provide a `text_render` fallback (required for voice, terminal, and graceful degradation).
7. Bump the catalog version and emit `component.catalog_changed`.

Components are **append-only by default** (Hard Rule 3). Removing a component breaks every manifest using it; deprecate first, remove after 90 days, document the migration path.
