A **brand kit** is the design-token surface the compiler reads to keep manifests on-brand. It's a JSON document matching `BrandTokensSchema` in `@atelier/schemas`.

## What each section drives

### Color (Vis-2 dark mode integration)

Both the light and dark surfaces flow from the same brand. Components consume CSS variables (`--cir-color-primary`, `--cir-color-neutral-N`); the renderer flips them via `[data-color-mode="dark"]` based on `intent.global_preferences.color_mode`.

### Typography (Vis-1)

`scale`, `letter_spacing`, `line_height`, and `opentype` flow into Tailwind via `--cir-tracking-*`, `--cir-leading-*`, `--cir-font-feature-settings`. Numeric columns in `<Table>` and `<StatCard>` values emit `data-tnum="true"` so hosts can opt into tabular numerals.

### Density (Vis-6)

The three (or more) named density variants. `resolveDensity(intent, route)` picks one per route based on the user's `intent.global_preferences.density` plus `density_overrides`. The renderer emits `data-cir-density` on the route's outermost wrapper; CSS variables (`--atelier-density-padding`, `--atelier-density-row-padding`, `--atelier-density-gap-multiplier`) project per-route via `[data-cir-density]` blocks.

Components that read density:

```text
Stack, Container, Card, Grid, List, Table, Queue, KPIRow,
StatCard, DetailView, Skeleton, VirtualList, VirtualTable
```

### Elevation (Vis-7)

Five-step elevation scale: `resting` / `hover` / `popover` / `modal` / `commandbar`. Paired light + dark recipes. Components consume via CSS variables.

### Motion (P-7 / Int-1)

`duration_scale` is the multiplier on the base duration token. Linear's "0.16x" is the reference. `respect_prefers_reduced` honours `prefers-reduced-motion: reduce` automatically. Components that have entry/exit animation (`Modal`, `Drawer`, `Toast`, `HoverCard`) honour the scale.

### Iconography (Vis-3)

`allowed_sets` declares which icon packs the host has installed. The `<Icon set="lucide" name="archive" />` resolver is in `@atelier/components`. Components like `<Button icon="archive">` go through the resolver — no hard-coded SVG paths in component code.

### Voice

Free-form prose the compiler reads to keep generated copy on-brand. Wired into the prompt; not a renderable surface.

## Code: consuming the brand

```ts
import type { BrandTokens } from '@atelier/schemas';
import brandKit from './brand_kits/aurora.json';

const tokens: BrandTokens = brandKit;
//   tokens.color.primary === '#6e56cf'
//   tokens.density.compact.padding === '0.5rem'
//   tokens.motion.duration_scale === '0.16'
```

## Where the kit fits in compile

```text
recipe + intent + capabilities + components + brand_kit
                    ↓
                 compiler
                    ↓
                 manifest
```

The compiler reads the brand kit alongside everything else. Density, elevation, motion, and color are consumed by the renderer at walk-time via CSS variables. Voice flows into prompt construction.

## Writing a kit

`atelier init` ships a default kit with the Atelier brand. To customise:

1. Copy `brand_kits/aurora.json` to `brand_kits/yours.json`.
2. Tweak the values. The schema enforces shape but is permissive about extra keys.
3. Wire it in `lib/cir-server.ts`:

   ```ts
   import yourBrand from '../brand_kits/yours.json';

   const services = configureCirRuntime({
     brandKit: yourBrand,
     // ...
   });
   ```

4. Run `pnpm exec atelier-schemas validate-data --strict` to confirm the file parses.

## Multi-brand apps

A single host can ship multiple brand kits and switch by route, persona, or intent rule. The compiler reads whichever kit the recipe references; manifests carry the kit version in `compiled_from.brand_kit_version`. Switching brands invalidates manifests for the affected routes.
