This page is the production checklist. The walkthrough version is at [Getting started → Deploying](/getting-started/deploying/); this page assumes you've already shipped a working dev deploy and now want to harden it.

## The four surfaces

1. **Host.** Next.js / Vite / Express / your Node server. Owns the routes, the API endpoints, the bundled React adapter.
2. **Vault.** `@atelier/vault-server` or a third-party vault speaking the [vault protocol](https://github.com/fragmatic-io/atelier/blob/main/docs/vault-protocol.md).
3. **Compiler.** Where `@atelier/compiler` runs. Inline in the host process for small deploys; on a dedicated worker pool past ~1k DAU.
4. **Static artifact registries.** `capabilities/`, `skills/`, `components/registry.json`, `policies/`, `recipes/`, served from the host or an edge CDN.

## Before you ship

### Environment variables

The feature paths below are **default-on** in the demo and reference host. Each ships a single opt-out env var (`ATELIER_*=off`); the legacy `CIR_*_ENABLED=0` form is honoured for one release cycle. See [Operations → Env vars](/operations/env-vars/) for the full list and the deprecation timeline.

| Variable                            | Required | Default | Purpose                                                                    |
| ----------------------------------- | -------- | ------- | -------------------------------------------------------------------------- |
| `GEMINI_API_KEY`                    | optional | unset   | LLM compiler key. Without it, `FallbackCompiler` runs.                     |
| `NEXT_PUBLIC_VAULT_URL`             | yes      | —       | Where the host's vault-client points. Defaults to `http://localhost:4001`. |
| `NEXT_PUBLIC_VAULT_FALLBACK`        | optional | unset   | `disabled` to forbid `localStorage` fallback when vault unreachable.       |
| `REDIS_URL`                         | optional | unset   | For `RedisManifestStore` / future `RedisTriggerBus`.                       |
| `ATELIER_COMPILER_TOOLS`            | optional | on      | `off` disables `ToolUsingCompiler` (Wave C-2). Default-on.                 |
| `ATELIER_CAPABILITY_RESOLVER`       | optional | on      | `off` disables capability scoping (C-3 / S-1). Default-on.                 |
| `ATELIER_RECIPE_RAG`                | optional | on      | `off` disables recipe RAG (`findRecipe` / C-5). Default-on.                |
| `ATELIER_MARKETPLACE`               | optional | on      | `off` disables the V-6 marketplace surface. Default-on.                    |
| `ATELIER_COMPILE_BUDGET`            | optional | on      | `off` disables `BudgetMeteredCompiler` (S-6). Default-on.                  |
| `CIR_COMPILE_BUDGET_TOKENS`         | optional | unset   | Token ceiling per window. Tuning knob; kept as `CIR_*` for one release.    |
| `CIR_COMPILE_BUDGET_TOKENS_PER_DAY` | optional | 50000   | Token-per-day cap. Tuning knob; kept as `CIR_*` for one release.           |
| `CIR_COMPILE_BUDGET_CALLS_PER_HOUR` | optional | 30      | Per-hour call cap. Tuning knob; kept as `CIR_*` for one release.           |
| `CIR_COMPILE_BUDGET_WINDOW_MS`      | optional | unset   | Window length in ms. Tuning knob; kept as `CIR_*` for one release.         |

### Secrets posture

- **Gemini API key** in your secret store (Doppler / AWS SSM / GCP Secret Manager). Rotate every 90 days.
- **Vault signing keys** never leave the vault host. The reference vault stores them as PEM files; production deploys use HSM / KMS-backed keys.
- **Redis credentials** scoped to least privilege; the manifest store doesn't need cluster admin.

### CI gates

The repo ships `actionlint` over Dependabot PRs (no `pull_request_target` skip). Match this in any fork:

```yaml
- name: Lint workflows
  run: |
    docker run --rm -v "$PWD:/repo" rhysd/actionlint:latest -color
```

Branch protection (set via the GitHub UI / `gh`):

- Require PR review.
- Require CI green.
- No force-push.
- No bypass for admins (or only for the named maintainer).

### Pages source

For the merged Atelier site at `/atelier/` (homepage + splash pages + developer docs all in one Starlight build):

> **Settings → Pages → Source: GitHub Actions.**

Until that toggle is flipped, the deploy step fails with a clear message from `actions/configure-pages`. Build steps still run on every PR; you get build-time validation regardless.

## Deploy patterns

### Single-process

Smallest viable deploy. Node host runs everything in-process:

```text
┌──────────────────────────┐
│  Node 22+ process        │
│  - Next.js host          │
│  - Compiler in-process   │
│  - Vault in-process      │
│  - MemoryManifestStore   │
│  - InMemoryTriggerBus    │
└──────────────────────────┘
```

Boot: `pnpm build && pnpm start`. Deploy target: Fly.io / Railway / Render / Vercel-Node.

Suitable up to ~1k DAU. Past that, the LLM call dominates request latency on cold path.

### Split compile-worker

Once the host's request rate justifies it:

```text
┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
│  Next.js     │────▶│  Compile worker  │────▶│  LLM provider │
│  host        │     │  Node pool       │     └──────────────┘
└──────────────┘     └──────────────────┘
       │                     │
       └─────▶ Redis manifest store ◀┘
```

Wire via `ServerManifestResolver`:

```ts
import {
  createBaselineManifestValidator,
  ServerManifestResolver,
  RedisManifestStore,
} from '@atelier/compiler';

const resolver = new ServerManifestResolver({
  store: new RedisManifestStore({ url: process.env.REDIS_URL! }),
  compileEndpoint: process.env.COMPILE_WORKER_URL!, // worker's HTTP endpoint
  validate: createBaselineManifestValidator({
    grantedFields: (input) => loadGrantedFields(input.user_id),
  }),
});
```

### Multi-region

For multi-region, you also need a distributed trigger bus. Wave S-4 (`RedisTriggerBus`) is the seam; until it lands, write a thin wrapper.

```text
us-east           eu-west            ap-south
  ↓                  ↓                   ↓
   ↘─── shared Redis manifest store ────↗
   ↘─── shared Redis trigger pubsub ────↗
```

## Health checks

The runtime exposes `/api/cir/health` (host implementation):

```ts
// app/api/cir/health/route.ts
export async function GET() {
  const checks = await Promise.all([
    services.compiler.ping(),
    services.manifestStore.ping(),
    services.triggerBus.ping(),
    services.dataResolver.ping?.(),
  ]);
  const ok = checks.every((c) => c.ok);
  return Response.json({ ok, checks }, { status: ok ? 200 : 503 });
}
```

Wire to your load balancer's health probes.

## Backups + restore

| Data                        | Backup target                                       |
| --------------------------- | --------------------------------------------------- |
| Vault profile JSON storage  | Daily snapshot to S3 (encrypted at rest).           |
| Manifest store (Redis)      | Optional — manifests are recomputable from sources. |
| Audit log                   | Forwarded to a durable sink (BigQuery / DataDog).   |
| Capability / skill registry | Source-controlled in git; tag releases.             |

The audit log is the most critical durable artifact — it's how you reconstruct what happened.

## Performance budgets

| Metric                         | Budget                    |
| ------------------------------ | ------------------------- |
| Hot-path render (cache hit)    | &lt;16ms                  |
| Cold-path compile              | 200ms-3s                  |
| Vault grant fetch              | &lt;50ms                  |
| Trigger publish → invalidation | &lt;100ms                 |
| Action dispatch                | &lt;100ms (excl. backend) |

Surface these in your APM. The audit log records every duration; aggregate.

## Rollouts

For a non-trivial host:

1. **Feature-flag major compiler upgrades.** New compiler model? Boot it on 1% of traffic; eval drift; widen.
2. **Stage compile worker rollouts.** Worker pool deploys are independent from host deploys; this is a good thing. Gradual rollout per region.
3. **Capability / skill bumps invalidate manifests.** Plan the rollout so cold-path compile traffic is bounded.
