This is the canonical reference for every environment variable Atelier reads. Defaults, ranges, what each var gates, and the deprecation timeline for the legacy `CIR_*` names live here.

## Reading guide

Three groups:

1. **Required / host config** — vault URL, LLM key, Redis. Set per deploy.
2. **Feature gates (`ATELIER_*`)** — boolean opt-out for default-on feature paths. The complete set is enumerated below.
3. **Tuning knobs (`CIR_COMPILE_BUDGET_*`)** — numeric thresholds for the budget metering. Kept as `CIR_*` for one release, then renamed to `ATELIER_*` with the same legacy-tolerant pattern.

## Naming convention

The `ATELIER_*` prefix replaces the legacy `CIR_*` prefix as part of the package rename. **All `CIR_*` env vars continue to be read for one release cycle** so existing deployments don't break — but new deployments should use the `ATELIER_*` form. The deprecation timeline for each gate is called out in the table below.

## Feature gates

Every gate below is **default-on**. The legacy `CIR_*_ENABLED=0` form is the historical opt-out; the new `ATELIER_*=off` form is the canonical opt-out going forward. Any other value (`'on'`, `'1'`, unset, empty string) is treated as default-on.

| New name                      | Legacy name                       | Default | Gates                                                | Flipped (commit / date)    |
| ----------------------------- | --------------------------------- | ------- | ---------------------------------------------------- | -------------------------- |
| `ATELIER_COMPILER_TOOLS`      | `CIR_COMPILER_TOOLS_ENABLED`      | on      | C-2 `ToolUsingCompiler` in `apps/demo`               | `d4fe259` / 2026-05-04     |
| `ATELIER_CAPABILITY_SCOPING`  | `CIR_CAPABILITY_SCOPING_ENABLED`  | on      | Two-stage compile (S-1) — only meaningful with tools | `d4fe259` / 2026-05-04     |
| `ATELIER_CAPABILITY_RESOLVER` | `CIR_CAPABILITY_RESOLVER_ENABLED` | on      | C-3 capability scoping resolver baseline             | _this commit_ / 2026-05-04 |
| `ATELIER_RECIPE_RAG`          | `CIR_RECIPE_RAG_ENABLED`          | on      | C-5 recipe RAG (`findRecipe` tool wiring)            | _this commit_ / 2026-05-04 |
| `ATELIER_MARKETPLACE`         | `CIR_MARKETPLACE_ENABLED`         | on      | V-6 marketplace endpoints in `@atelier/vault-server` | _this commit_ / 2026-05-04 |
| `ATELIER_COMPILE_BUDGET`      | `CIR_COMPILE_BUDGET_ENABLED`      | on      | S-6 compile-budget enforcement                       | _this commit_ / 2026-05-04 |

### Deprecation timeline

- **Today (2026-05-04):** Both names are honoured; `ATELIER_*=off` is the recommended opt-out.
- **Next release cycle:** Legacy `CIR_*_ENABLED=0` continues to work. A console warning is emitted when the legacy form is observed (TODO).
- **Release after that:** Legacy names removed. Hosts on the legacy form must migrate to `ATELIER_*=off`.

## Test gates

| New name                  | Legacy name           | Default | Gates                                                                         |
| ------------------------- | --------------------- | ------- | ----------------------------------------------------------------------------- |
| `ATELIER_EMBEDDING_TESTS` | `CIR_EMBEDDING_TESTS` | unset   | Heavy real-provider embedding integration tests in `@atelier/recipe-resolver` |

Set to `1` to run the gated tests. Both names accepted for one release cycle. Not a feature flag — purely a test-suite gate to keep CI off paid embedding endpoints by default.

## Tuning knobs

These are not feature gates; they are numeric thresholds the budget metering reads when `ATELIER_COMPILE_BUDGET` is on. Kept as `CIR_*` for one release cycle, then renamed to `ATELIER_*` with the same legacy-tolerant pattern.

| Variable                            | Default | Range               | Purpose                                                          |
| ----------------------------------- | ------- | ------------------- | ---------------------------------------------------------------- |
| `CIR_COMPILE_BUDGET_TOKENS`         | unset   | positive integer    | Token ceiling per window (sliding-window form).                  |
| `CIR_COMPILE_BUDGET_TOKENS_PER_DAY` | 50000   | positive integer    | Per-day token cap used by the demo seed.                         |
| `CIR_COMPILE_BUDGET_CALLS_PER_HOUR` | 30      | positive integer    | Per-hour call cap used by the demo seed.                         |
| `CIR_COMPILE_BUDGET_WINDOW_MS`      | unset   | positive integer ms | Sliding window length (with `CIR_COMPILE_BUDGET_TOKENS`).        |
| `CIR_SCOPING_MODEL`                 | unset   | string (model id)   | Override the stage-1 model name in `TwoStageCapabilityResolver`. |
| `CIR_DIFF_BASE`                     | unset   | string (git ref)    | Eval diff base for `cir-evals`.                                  |

## How the gate pattern works

Every `ATELIER_*` feature gate follows the same three-line pattern:

```ts
const fooEnv = process.env['ATELIER_FOO'];
const legacyDisabled = process.env['CIR_FOO_ENABLED'] === '0';
const useFoo = !legacyDisabled && fooEnv !== 'off';
```

Three rules:

1. **Default behaviour is ON** unless either env var disables.
2. **`ATELIER_FOO=off` is the new opt-out.** Any other value (`'on'`, `'1'`, unset) is on.
3. **`CIR_FOO_ENABLED=0` is the legacy opt-out** — kept honoured for one release cycle so existing deployments don't break.

This pattern is set by `d4fe259` for `CIR_COMPILER_TOOLS_ENABLED` and applied uniformly to the remaining 5 gates by this commit.
