`atelier validate` is the pre-flight check the CLI runs against your project. It detects what tooling you have wired up (TypeScript, ESLint, Vitest, package manager) and runs the appropriate checks inline — no shell-out to a `pnpm validate` script the consumer might not have.

Sprint 1.2 reimplemented the command around real per-check runners. Earlier waves shelled out to `pnpm validate` blindly, which only worked inside the Atelier monorepo and gave external consumers an opaque "command failed" with no actionable signal.

## What it runs

Checks run in this order:

1. **`tsc --noEmit`** — typecheck. Skipped when no `tsconfig.json` (or `tsconfig.base.json`) is present.
2. **`eslint .`** — lint. Skipped when no ESLint config file (`eslint.config.{js,mjs,cjs,ts}` or `.eslintrc.*`) is present.
3. **The consumer's `test` script** via the detected package manager — pnpm, npm, or yarn. Skipped when `package.json` has no `test` script (or a placeholder `echo "no tests"` form).
4. **Atelier schema validation**, always run for whichever artefacts are present at the project root:
   - `capabilities/*.json` against `CapabilitySchema`.
   - `skills/**/*.skill.md` against `SkillSchema` (YAML frontmatter via `parseSkillMarkdown`).
   - `policies/*.json` against `PolicySchema`.
   - `recipes/*.json` against `ManifestSchema`.
   - `brand-kit.json` against `BrandKitSchema`.
   - `components/registry.json` against `ComponentRegistrySchema`.

Schemas come from `@atelier/schemas` — the same source of truth as `atelier-schemas validate-data`. There is no parallel registry.

## Stack detection

Detection is a single pass of `existsSync` / `readFile` over a small set of well-known files. Cheap and best-effort; anything we can't detect with confidence becomes `false` and the runner reports `· skipped (<reason>)`.

| Signal          | Sniffed for                                                                           |
| --------------- | ------------------------------------------------------------------------------------- |
| TypeScript      | `tsconfig.json`, `tsconfig.base.json`                                                 |
| ESLint          | `eslint.config.{js,mjs,cjs,ts}`, `.eslintrc.{,js,cjs,json,yaml,yml}`                  |
| Vitest          | `vitest.config.{ts,js,mjs,cjs}` OR a `test` script that invokes `vitest`              |
| Tests           | Any non-placeholder `test` script in `package.json`                                   |
| Package manager | `pnpm-lock.yaml` → pnpm; `yarn.lock` → yarn; `package-lock.json` → npm; default `npm` |
| Monorepo        | `pnpm-workspace.yaml` (pnpm), or `workspaces` in `package.json` (npm/yarn)            |

Binary resolution for `tsc` and `eslint`: first `<root>/node_modules/.bin/<bin>` (consumer-pinned), then PATH. The CLI does NOT bundle TypeScript or ESLint — the consumer picks their own version.

## Output

Default text output is a tabular summary:

```
atelier validate
────────────────────────────────────────
PASS  TypeScript      ./                 12 file(s), 0 error(s)
PASS  ESLint          ./                 42 file(s), 0 error(s)
PASS  Vitest          ./                 ok
PASS  Capabilities    ./capabilities/    4 file(s), 0 error(s)
PASS  Skills          ./skills/          2 file(s), 0 error(s)
PASS  Policies        ./policies/        3 file(s), 0 error(s)
SKIP  Brand kit       ./brand-kit.json   skipped (no brand-kit.json)
SKIP  Recipes         ./recipes/         skipped (no recipes/ directory)
SKIP  Components      ./components/registry.json  skipped (no components/registry.json)
────────────────────────────────────────
PASS  All checks passed (6/9)
```

Failures show the file + line + reason in a detail block below the summary:

```
FAIL  3 check(s) failed, 4 passed, 2 skipped

  Capabilities failures:
    /repo/capabilities/broken.json — /kind Invalid enum value (+1 more)
  Policies failures:
    /repo/policies/broken.json — /description Required
  Skills failures:
    /repo/skills/broken.skill.md — /capabilities_used Required (+1 more)
```

## Flags

| Flag           | What it does                                                                                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--strict`     | Treat skipped checks as failures. CI mode: every advertised check must actually run.                                                                                                                                            |
| `--json`       | Emit a stable JSON payload instead of the human table.                                                                                                                                                                          |
| `--only=<set>` | Comma-separated subset. Tokens: `typecheck`, `lint`, `test`, `schemas` (expands to all six Atelier validators), or any individual check id (`capabilities`, `skills`, `policies`, `brandKit`, `recipes`, `componentsRegistry`). |

## Exit codes

| Code | Meaning                                                           |
| ---- | ----------------------------------------------------------------- |
| `0`  | All detected checks passed.                                       |
| `1`  | At least one check failed (or skipped under `--strict`).          |
| `2`  | Configuration error — no `package.json` at the working directory. |

## `--json` shape

The JSON output is stable. Consumers can pipe it into a CI dashboard:

```jsonc
{
  "ok": true,
  "strict": false,
  "results": [
    {
      "id": "typecheck",
      "label": "TypeScript",
      "status": "pass", // pass | fail | skip
      "scope": "./",
      "fileCount": 12,
      "errorCount": 0,
      "reason": null, // string for skip / fail summaries
      "issues": [],
      "durationMs": 482,
    },
    // ... one row per check
  ],
}
```

## Workflow tips

- Run `atelier validate --strict --json` in CI. The `--strict` flag catches "you forgot to add an ESLint config" before it ships; the JSON output threads cleanly into status pages.
- For local iteration, `atelier validate --only=schemas` is fast — it skips the spawn-heavy typecheck/lint/test trio and just validates your `capabilities/`, `skills/`, etc.
- The schema runners short-circuit to `skip` on missing directories, so consumers using a subset of Atelier (just `skills/`, no `policies/`, etc.) don't see noise.
- If you want the legacy "shell out to my repo's `pnpm validate` script" behaviour back, your script already does that — you can call `pnpm validate` directly, or wire `atelier validate` into a `validate` script of your own.
