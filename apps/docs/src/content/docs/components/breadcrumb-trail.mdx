Wave Nav-4 ships a Stripe-style drilldown breadcrumb with a shareable URL. The trail serialises into a `?_trail=` query parameter so deep-link sharing works; the React hook owns state and the URL round-trip; the host stays the router.

## The shape

```tsx
import { Breadcrumb, useTrail } from '@atelier/react';

function Layout() {
  const { trail, push, pop, replaceTo, clear } = useTrail({ syncToUrl: true });

  return (
    <Breadcrumb
      trail={trail}
      onNavigate={(segment) => replaceTo(segment.id)}
      homeLabel="Charges"
      separator="›"
    />
  );
}
```

When the user navigates, `push({ id, label })` adds a segment. The hook calls `window.history.replaceState` to update `?_trail=` without a full route change. Reload the page; the trail rehydrates from the URL.

## The wire format

```text
/charges?_trail=charges|ch_xxx_ch_xxx|refund_r_yyy
```

- `|` separates segments.
- `_` escapes within segments (so a colon-laden id doesn't collide with a delimiter).
- The first segment is implicit "home" — the page-root.

The serializer (`serializeTrail`) and parser (`parseTrail`) live in `packages/components/src/breadcrumb/trail.ts`. Both round-trip exactly.

## Stripe inspiration

Stripe's dashboard ships breadcrumbs like:

```text
Charges › ch_3MjxQv2eZvKYlo2C1gRrJBwM › Refund r_3MjxQv2eZvKYlo2C
```

Each segment is clickable; clicking a parent collapses everything past it. The whole trail is shareable via the URL.

Atelier's `<Breadcrumb>` matches this. The trail is the canonical state; the URL is the wire format; the host's router stays untouched.

## Code: pushing segments

```tsx
import { useTrail } from '@atelier/react';

function ChargeDetail({ chargeId }) {
  const { push } = useTrail({ syncToUrl: true });
  const onSelectRefund = (refundId) => {
    push({ id: `refund:${refundId}`, label: `Refund ${refundId}` });
    // navigate to the refund detail
  };
  // ...
}
```

The hook's `push` updates state + calls `replaceState`. No re-render of the host route.

## Back-compat with `<Breadcrumb items={...} />`

The pre-Nav-4 prop API still works:

```tsx
<Breadcrumb
  items={[
    { label: 'Charges', href: '/charges' },
    { label: 'ch_xxx', href: '/charges/ch_xxx' },
  ]}
/>
```

The new `trail` + `onNavigate` API is the recommended one for app-shell breadcrumbs; the `items` API is fine for static contextual breadcrumbs.

## SSR behaviour

When `window` is unavailable (server render), `useTrail()` returns an empty trail. The `?_trail=` query is read on first client render. No flash-of-content; the breadcrumb just expands once the trail is hydrated.

## Custom serialization

Override the serializer if `?_trail=...` collides with a host's existing query parameter:

```ts
import { useTrail } from '@atelier/react';

const trail = useTrail({
  syncToUrl: true,
  queryKey: '_b', // → ?_b=...
  // or fully custom:
  serialize: (trail) => myCustomEncoder(trail),
  parse: (str) => myCustomDecoder(str),
});
```
