`@atelier/components` ships 67 baseline React primitives with composition rules and per-component metadata. The compiler picks from these. Demos compose from these. Custom bindings (which the framework discourages — see [baseline-vs-custom](/components/baseline-vs-custom/)) are a last resort.

## The 67 baseline primitives

## Composition rules

Every component declares what it can contain and what it can be contained by. The compiler reads these rules; the validator enforces them.

```json
// components/registry.json (excerpt)
{
  "Stack": {
    "can_contain": "*",
    "min_children": 1,
    "max_children": 50
  },
  "Card": {
    "can_contain": ["Stack", "Grid", "DetailView", "Markdown", "Chart"]
  },
  "Form": {
    "can_contain": [
      "TextInput",
      "NumberInput",
      "DateInput",
      "Select",
      "MultiSelect",
      "FileUpload",
      "RichText"
    ]
  }
}
```

The full `composition-rules.json` ships at `components/composition-rules.json`, generated from `@atelier/components` metadata via `pnpm components:sync`.

## Per-component prop schemas

`ManifestComponentContract` (the canonical schema landed alongside Wave M) defines per-component prop schemas. The validator confirms that every node's props match its declared component's contract — no `?? []` defaults at the renderer layer.

```ts
import { COMPONENT_CONTRACTS } from '@atelier/components';

const queueContract = COMPONENT_CONTRACTS.Queue;
//   queueContract.props === ZodObject ({...})
//   queueContract.actions === ['onPrimaryAction', 'onSecondaryAction', ...]
//   queueContract.compositionRole === 'data-bound-collection'
```

## Dark mode (Vis-2)

Every component ships paired light + `dark:` Tailwind utilities. Regression gate at `test/_variants-dark.test.ts`. Toggle `intent.global_preferences.color_mode` and the renderer flips `[data-color-mode="dark"]` automatically.

## Density (Vis-6)

The density-aware components read `data-cir-density` from the route wrapper:

```text
Stack, Container, Card, Grid, List, Table, Queue, KPIRow,
StatCard, DetailView, Skeleton, VirtualList, VirtualTable
```

CSS variables (`--atelier-density-padding`, `--atelier-density-row-padding`, `--atelier-density-gap-multiplier`) project per-route via `[data-cir-density]` blocks.

## Variants (P-10 / Vis-4)

Most components ship `variant` and `size` axes. P-10 covered 24/56; Vis-4 fills the remaining 32 (inputs, charts, niche specialised). See [variants](/components/variants/).
