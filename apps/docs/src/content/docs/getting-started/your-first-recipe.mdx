A **recipe** is the file humans author. It declares the persona's intent surfaces, the granted capabilities, the candidate skills, and the policy obligations. The compiler turns it into a manifest.

This page walks you through writing one from scratch.

## What a recipe looks like

```json
// recipes/founder.json
{
  "id": "recipes:founder",
  "version": "1.0.0",
  "persona": "founder",
  "description": "Investor + customer email triage with a bias toward action.",
  "intent_defaults": {
    "global_preferences": {
      "density": "compact",
      "color_mode": "system",
      "modal_tolerance": "low",
      "automation_trust": "drafts_only"
    },
    "lenses": {
      "email": "founder_inbox",
      "today": "decisions_first"
    },
    "rules": [
      {
        "scope": "email",
        "rule": "Investor and customer emails surface above newsletters.",
        "version": 1
      },
      {
        "scope": "*",
        "rule": "Never auto-send. Drafts only. Always confirm.",
        "version": 1,
        "locked": true
      }
    ]
  },
  "capability_grants": [
    "thread.list",
    "thread.read",
    "thread.archive",
    "thread.unarchive",
    "task.create_from_thread",
    "task.list",
    "task.complete",
    "task.snooze",
    "task.reopen",
    "task.unsnooze"
  ],
  "candidate_skills": ["email-triage", "task-extraction", "decision-separation"],
  "policy_obligations": [
    "reversibility_surfaced",
    "no_destructive_actions_without_confirm",
    "data_scope_within_grant"
  ],
  "routes": [
    { "path": "/today", "title": "Today" },
    { "path": "/thread/[id]", "title": "Thread" },
    { "path": "/settings/intent", "title": "Intent settings" }
  ]
}
```

Every field is declarative. The compiler reads this, the user's actual `IntentProfile` (which may diverge from the defaults), and the candidate skills, then produces a `Manifest` JSON document that the runtime walks.

## Authoring it

<Steps>

1. **Scaffold a new app.** From an empty directory:

   ```bash
   pnpm dlx @atelier/cli init my-app
   cd my-app
   pnpm install
   ```

   This drops a working Next.js + Atelier project — registry directories (`capabilities/`, `skills/`, `components/`, `policies/`, `recipes/`), a wired `lib/cir-server.ts`, and a sample `recipes/default.json`.

2. **Open `recipes/default.json`.** It already has the shape above. Edit `persona`, `description`, and `intent_defaults` to match your use case.

3. **Declare the capabilities you'll grant.** Anything in `capability_grants` must exist as a file in `capabilities/`. The CLI scaffolds a few for you; add your own as JSON files matching the `CapabilitySchema`:

   ```json
   // capabilities/thread.archive.json
   {
     "id": "thread.archive",
     "kind": "action",
     "version": "1.0.0",
     "input": { "thread_id": { "type": "string" } },
     "output": { "archived_at": { "type": "string", "format": "date-time" } },
     "side_effects": ["mutates:thread_state"],
     "permissions": ["thread:write"],
     "confirmation": "modal",
     "rate_limit": "100/min/user",
     "reversible": true,
     "rollback": "thread.unarchive",
     "salience_level": "medium"
   }
   ```

   Run `pnpm exec atelier-schemas validate-data` to confirm the file parses.

4. **Add the matching skills.** A skill is markdown with a YAML frontmatter:

   ```yaml
   # skills/email-triage.skill.md
   ---
   name: email-triage
   version: 1.0.0
   description: Categorize an email thread by urgency and required action
   capabilities_used:
     - thread.list
     - thread.read
     - thread.archive
     - task.create_from_thread
   when_to_use: |
     When the user opens a thread that contains explicit asks, deadlines,
     or commitments. Not for newsletters or notifications.
   when_not_to_use: |
     Marketing emails. Auth codes. Receipts.
   ---
   ```

5. **Wire the recipe in `lib/cir-server.ts`.** The CLI's scaffold already loads `recipes/*.json`; just confirm your new file is in the directory.

6. **Boot.**

   ```bash
   pnpm dev
   ```

7. **Visit `http://localhost:3000`.** First request to a route triggers a compile against your recipe. The audit tail (in another terminal: `pnpm atelier dev --tail-only`) shows the compile fire.

</Steps>

## What the compiler does with it

The compiler's input is the recipe + the user's intent + the candidate skills + the component catalog. Its output is a manifest tree. For `/today` against the founder recipe above, you might get something like:

```json
{
  "manifest_id": "m_a1b2c3",
  "compiled_from": {
    "recipe_id": "recipes:founder",
    "intent_profile_version": 7,
    "compiler_model": "gemini-1.5-pro"
  },
  "routes": [
    {
      "path": "/today",
      "title": "Today",
      "layout": {
        "component": "Stack",
        "children": [
          {
            "component": "Queue",
            "props": { "title": "Decisions", "density": "compact" },
            "data": { "source": "thread.list", "filter": "requires_decision = true" },
            "actions": ["task.create_from_thread", "thread.archive"]
          },
          {
            "component": "Queue",
            "props": {
              "title": "Tasks due this week",
              "density": "compact",
              "group_by": "due_date"
            },
            "data": { "source": "task.list", "filter": "due_within = 7d AND status != done" },
            "actions": ["task.complete", "task.snooze"]
          }
        ]
      }
    }
  ],
  "policies_satisfied": [
    "reversibility_surfaced",
    "no_destructive_actions_without_confirm",
    "data_scope_within_grant"
  ]
}
```

The `<Queue>` primitive is the marketplace-pivot baseline that replaced custom `IssueQueue` / `TaskQueue` / `DecisionQueue` bindings. The compiler picked it because the recipe's intent says "compact + decision-first" and the catalog's `Queue` description says "stack of items, optional grouping, optional pinning, supports per-row actions".

## Inspecting a manifest offline

You can compile against a recipe without running the host:

```bash
pnpm atelier compile fixtures/intent.json \
  --capabilities capabilities/ \
  --components components/registry.json \
  --recipe recipes/default.json
# → writes manifests/m_xxx.json

pnpm atelier inspect manifests/m_xxx.json
# pretty-prints the tree
```

This is the fastest way to iterate on a recipe — change a rule, re-compile, see what shifts.

## When to write a custom binding instead

Almost never. Read [`baseline-vs-custom`](/components/baseline-vs-custom/) before reaching for the escape hatch. The marketplace pivot collapsed 17 custom bindings across the three reference demos to **zero**. Your app probably doesn't need any either.
