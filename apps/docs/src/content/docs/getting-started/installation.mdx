This page is the true zero-to-running walkthrough. If you have never seen Atelier before — if you do not know what a manifest is, if you have never opened the demo — start here. Every command is meant to be copied, pasted, and run as-is.

## What you need

- **Node.js 22 or 24.** Atelier supports both. Check with `node --version`. If you don't have it: install [`fnm`](https://github.com/Schniz/fnm) or [`nvm`](https://github.com/nvm-sh/nvm) and run `fnm install 22` or `nvm install 22`.
- **pnpm 10+.** Atelier is a pnpm workspace. Install with `npm install -g pnpm`.
- **Git.** You probably have it. Check with `git --version`.
- **A Gemini API key (optional).** Without one, the `FallbackCompiler` ships hand-written manifests so the demo still boots end-to-end. With one, you watch the real compiler run — and that's the whole point of the framework.

That's it. No Docker. No Postgres. No Redis. Atelier's defaults are all in-memory or local-disk.

## Quick start — standalone (Sprint 1.1)

The fastest path is `npx -y @atelier/cli init`. This scaffolds a fresh
Next.js 15 (or Vite + React 19) project that depends on
`@atelier/runtime`, `@atelier/react`, `@atelier/components`, and
`@atelier/compiler` from npm — no monorepo dependency.

```bash
# Next.js 15 (default host)
npx -y @atelier/cli init my-app

# OR Vite + React 19
npx -y @atelier/cli init my-app --host=vite

cd my-app
pnpm dev          # boots `atelier vault dev` (4001) + the dev server (3000)
# open http://localhost:3000
```

The scaffold ships with one starter recipe, one starter policy, two
starter capabilities, one starter skill, plus a `brand-kit.json` and an
`.env.local.example`. Drop your Gemini key in `.env.local` and the real
compiler runs; without it, the deterministic
`GenericFallbackCompiler` ships hand-written manifests so the page still
renders.

If you want to dig into the framework itself — explore the demos, run
the eval suite, watch the compiler render Aurora — clone the repo
instead. The walkthrough below is that path.

## The walkthrough — explore the monorepo

<Steps>

1. **Clone the repo.**

   ```bash
   git clone https://github.com/fragmatic-io/atelier.git
   cd atelier
   ```

2. **Install dependencies.** This pulls down the workspace, builds the published packages once, and links them into the demos. About 60 seconds on a warm cache.

   ```bash
   pnpm install
   ```

3. **(Optional) Drop in your Gemini key.** Without this step the demo still boots, just with the deterministic fallback compiler. With it, the real LLM compiler is exercised every time you change intent.

   ```bash
   cp apps/demo/.env.local.example apps/demo/.env.local
   # Open apps/demo/.env.local and set GEMINI_API_KEY=...
   ```

   <Aside type="tip">
     Don't have a Gemini key? Skip this step. Everything below still works. The audit stream will
     show the fallback compiler running instead.
   </Aside>

4. **Boot the demo.** This single command spawns the intent vault server (port 4001) AND the Next.js demo (port 3000) with prefixed log streams. Ctrl-C tears both down cleanly.

   ```bash
   pnpm demo
   ```

   You'll see two banners scroll past:

   ```text
   [vault]  ▲ Atelier vault listening on http://localhost:4001
   [demo]   ▲ Next.js  ready in 1.2s
   [demo]   - Local:        http://localhost:3000
   ```

5. **Open the demo in your browser.**

   ```text
   http://localhost:3000
   ```

   First visit lands on `/onboarding`. You'll see two paths:
   - **Checkbox grant.** Pick the lenses you want to share with the demo and click "Grant". A vault token is minted; you're redirected to `/today`.
   - **"Or describe yourself in your own words →".** Type a few sentences. The compiler runs `compileIntentProfile()` on your free text and produces a draft `IntentProfile`. You review and edit it on `/onboarding/review` before saving.

6. **Watch the manifest compile.** Open a second terminal and tail the audit stream:

   ```bash
   pnpm atelier dev --tail-only
   ```

   Now interact with the demo:
   - Click any thread on `/today` → the runtime fetches the thread, dispatches `thread.read`.
   - Visit `/settings/intent` → toggle the **density** to `compact` or `spacious`. Watch the audit stream show a new `manifest.compiled` event. The `/today` route reshapes — `<Grid columns=3>` becomes `<List>` becomes `<Grid columns=2 large>` depending on what you picked. **That is the framework at work.**
   - Click **Archive** on a thread → modal confirmation; click confirm → optimistic UI; an undo toast pops up; click **↶ Undo** within 5s and the action rolls back.

7. **Trigger a recompile from a third shell.** Atelier's trigger bus is exposed at `/api/triggers/publish`. Push one and watch the browser refetch via SSE:

   ```bash
   curl -XPOST http://localhost:3000/api/triggers/publish \
     -H 'content-type: application/json' \
     -d '{"type":"user.recompile_route","user_id":"demo-user","manifest_id":"m_demo_today","route":"/today"}'
   ```

   The audit tail prints `manifest.invalidated` → `manifest.compiled` → `manifest.served`. The page shifts. Tokens tick. **You have run an Atelier system end-to-end.**

</Steps>

## Verifying the install

Atelier ships a single command that runs the full validation chain — license headers, typecheck, lint, format check, component registry sync, schema-validated artifact data, plus the test suite.

```bash
pnpm validate
```

For the fast pre-push variant (everything except tests):

```bash
pnpm validate:fast
```

The test suite alone is `pnpm test` and runs ≈2002+ tests across ≈140 files at the time of this writing.

## Common issues

- **`pnpm: command not found`** — Run `npm install -g pnpm` then re-open your shell.
- **`Node version mismatch`** — Atelier requires `node >=22`. Install via fnm/nvm; the repo's `.nvmrc` declares `22`.
- **`Port 3000 / 4001 already in use`** — Another process is bound. Kill it (`lsof -i :3000`) or pass `--port` to `pnpm demo`.
- **`Vault unreachable, falling back to localStorage`** — The vault didn't start (check the `[vault]` log lines). Start it manually with `pnpm atelier vault dev --port 4001` and retry.
- **`auth_failed: true` in audit events** — Your `GEMINI_API_KEY` is invalid or revoked. Either replace it or remove it; the fallback compiler will take over.

## What you have running

- `apps/demo` — the personalisation showcase. LLM-assisted onboarding, intent profile editing, dark-mode toggle, optimistic UI, undo toasts. Boot individually with `pnpm --filter @atelier/demo dev`.
- `apps/demo-dummyjson` — Marigold, the e-commerce catalog with lens switching (compact / cozy / spacious), bulk cart actions, hover-card product previews. `pnpm --filter @atelier/demo-dummyjson dev`.
- `apps/demo-github` — Octant, the issue-queue with real-mutation optimistic archive, undo within 5s, hover cards on `#issue` references, hierarchy treatment for assigned-to-me. `pnpm --filter @atelier/demo-github dev`.
- `@atelier/vault-server` — the reference intent vault on port 4001. JWT-signed grants, ed25519 keys, JSON-file storage. Run with `pnpm atelier vault dev`.
