## The problem

Modern operational software ships static interfaces. A team of designers and
engineers decides what the queue looks like, what the dashboard shows, what the
review screen contains — and that's what every operator sees. If support ops,
sales ops, compliance, or engineering ops needs a different surface over the
same systems of record, they file a feature request, clone a dashboard, or build
another internal tool.

This is fundamentally backwards once an LLM can reliably translate operational
intent into a policy-validated manifest. The compiler can do it on demand, per
role, per workflow, recomputed only when something material changes.

## Why not just hand-write React per user?

Three reasons:

1. **Token cost.** Free-form HTML/CSS/JSX generation is hundreds of tokens per element. A component name (`<Queue>`) is 1-3 tokens. An 83-component catalog covers most web app patterns at a fraction of the cost.
2. **Safety.** Components are pre-vetted for accessibility, responsive behaviour, security. Free-form HTML is an XSS vector waiting to happen.
3. **Consistency.** When every screen is composed from the same primitive vocabulary, the user gets a coherent experience: same motion, same density, same a11y conventions.

## Why not just stuff everything in one giant prompt?

That's how Atelier started. It works at small scale. It breaks at:

- **>200 capabilities.** Token budget blown; the LLM ignores half.
- **>50 components.** Same problem.
- **Validation cascades.** When a manifest violates a policy, the LLM never gets to fix its own mistake — it falls through to a deterministic fallback.
- **Multi-route apps.** Each route is compiled independently; chrome and brand drift across routes.

Wave C (compiler evolution) replaces "single big prompt" with **a single tool-using agent + validation feedback loop**. The agent calls `lookupCapability`, `findComponent`, `validateDraft` as it composes. Tools + reflection capture ~80% of multi-agent benefit at ~20% of cost.

## Who is this for?

**You run operational teams with too many internal tools.** Support ops,
sales/revenue ops, marketplace ops, compliance/risk ops, and engineering ops
all end up with role-specific queues, review screens, admin panels, and
dashboards. App builders prove those teams will pay for internal software, but
the next bottleneck is maintaining many slightly different UIs over the same
systems. Atelier lets the organisation define capabilities and policies once,
then compile policy-safe interfaces per role or workflow.

**You ship a SaaS product with operational users.** Your customers complain
that the admin UI is too dense / too sparse / too cluttered / too sterile.
Different teams want different review flows and action surfaces. Customisation
toggles plus feature flags become unmaintainable. Atelier's intent profile
collapses that into one architecture: the user describes how they work, the
compiler emits a policy-safe surface over capabilities you already own.

**You ship a developer tool.** Your power users build their own Linear / Notion / Raycast workflows. You want them to compose new views without writing React. The marketplace primitive — `atelier://author/persona@version` — turns recipe-publishing into a first-class operation.

**You ship a horizontal platform.** B2B vertical apps need quick spin-ups. The vertical-specific UX shouldn't require an engineering team per vertical. Atelier's recipes + skills lets a domain expert author the persona; the compiler does the rest.

## Alternatives

| Tool / pattern                          | Strength                           | Where it falls short for personalised UI                                                                                                                |
| --------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plain React / Vue / Svelte              | Best-in-class authoring experience | Static. Personalisation = feature flags + props.                                                                                                        |
| Server-driven UI (Airbnb / Lyft / Meta) | Layout JSON over the wire          | Hand-authored on the server. No LLM compile loop. No intent vault.                                                                                      |
| Retool-style app builders               | Fast internal tools over real data | The app shape is still authored and maintained. Role-specific dashboard sprawl returns as the organisation scales.                                      |
| v0 / Bolt / Tambo / A2UI                | Free-form generation               | Generates net-new apps from a prompt. Doesn't continuously personalise an existing app's UI per user. No baseline component vocabulary, no marketplace. |
| Rete / no-code builders                 | Drag-and-drop                      | The user authors layouts. Doesn't translate intent into structure automatically.                                                                        |
| MCP                                     | Capability protocol                | Just the capability layer. No render layer, no intent vault, no compile loop. Atelier sits on top of MCP-style capability definitions.                  |

Atelier picks one specific niche: **continuously recompile operational UI per
role/workflow, on demand, against a known capability surface, policy set, brand
kit, and component vocabulary.** It is not for net-new app generation; it is for
adapting what already exists.

## What you give up

- **Hand-pixel control.** The compiler picks the components. If you want a 6px-margin between two specific items on `/today` for `vid@`, you write a recipe rule, not a CSS file.
- **Authored UX choreography.** Multi-step flows that depend on micro-interactions can be hard to express in a recipe. You'll find yourself writing skills + custom bindings for those.
- **Fully offline.** The compiler is online by default. There's a `FallbackCompiler` that ships hand-written manifests for offline / no-key boot — but the primary path involves an LLM call.
- **Compiler-free dev loop.** During development, the cold path takes 200ms-3s. Most of that is the LLM round-trip. The hot path is sub-frame; the cold path is the trade-off.

## What you get

- **Role/workflow-specific UI without role/workflow-specific code.** The compiler emits a manifest that matches the operator's context, not the one a static dashboard guessed.
- **Cache invalidation as a first-class architecture.** Triggers, not stale-while-revalidate prayers.
- **Auditable everything.** Every compile, every action, every policy validation fires through a `StreamingAuditSink`.
- **A marketplace.** Recipes are signed bundles. `atelier://acme/email-triage@1.0.0` is a thing you can publish, consume, and trust.

## What we are not pursuing

- Arbitrary "fully dynamic UI" for every software category.
- Consumer landing pages, games, canvas editors, or brand-heavy websites.
- Free-form generated React/HTML as the production path.
- Replacing design systems; Atelier consumes brand kits and mature primitives.
- Replacing every Retool-style builder immediately; the wedge is operational
  workbenches whose maintenance cost grows with roles, queues, and policies.
