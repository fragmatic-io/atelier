The marketplace browse surface lets users **find a recipe**, **see whether it works**, and **install it**. V-6.c shipped the baseline `<MarketplaceBrowser>`. V-6.d added review-state pills. **Sprint 2.4** (this page) adds **compile-quality scorecards** — a 🟢/🟡/🔴 dot on every card that answers "does this thing currently pass the eval gate?"

This page documents the rendered surface and shows what hosts wire to drive it.

## What you see

When `<MarketplaceBrowser>` mounts against a `MarketplaceClient` with both `reviewState` and `scorecard` opted in, each card lists:

- **Persona name** (large) — from `address.persona`.
- **Version pill** — from `address.version`.
- **Review-state pill** — from `listing.reviewState`, when not `approved` (V-6.d).
- **Compile-quality scorecard pill** — 🟢/🟡/🔴 dot keyed off `summariseScorecard()` (Sprint 2.4).
- **Author display name + description + domain / brand-kit chips** — V-6.c baseline.

The scorecard pill carries a native `title` tooltip listing the failed checks, and clicking it expands a `<MarketplaceScorecardPanel>` row beneath the card showing every check, the cost breakdown (when present), the last-eval timestamp, and the reference versions block.

## The scorecard shape

```ts
import {
  CompileQualityScorecardSchema,
  summariseScorecard,
  type CompileQualityScorecard,
} from '@atelier/schemas';
```

Five binary checks, in canonical order:

| Check      | Passes when…                                                   | Hard / soft |
| ---------- | -------------------------------------------------------------- | ----------- |
| `compile`  | The compiler returned a manifest (no fallback / no error)      | hard        |
| `schema`   | The manifest validates against `ManifestSchema`                | hard        |
| `policy`   | No error-severity baseline policy violations fired             | hard        |
| `snapshot` | `manifest_shape_hash` matches the previously-recorded baseline | soft        |
| `cost`     | p95 compile cost ≤ the persona's declared compile budget       | soft        |

Hard failures are red; soft failures only are amber; everything passes is green.

`summariseScorecard()` is exported alongside the schema:

```ts
const summary = summariseScorecard(scorecard);
//   summary.status        : 'green' | 'amber' | 'red'
//   summary.failedChecks  : ('compile' | 'schema' | 'policy' | 'snapshot' | 'cost')[]
```

## Where the scorecards come from

The browser does NOT compute scorecards itself — it reads them from the client. Three host-side sources produce the same shape:

1. **V-6.e nightly deterministic gate** ([`@atelier/eval-marketplace`](/atelier/marketplace/eval-gate/)). No LLM, no token cost; the optional `cost_usd` / `cost_p95_usd` / `compile_duration_ms` fields are absent.
2. **Sprint 2.1 real-LLM eval suite** (sibling agent's `@atelier/eval-llm`). Carries the cost numbers and the duration measured against the real model.
3. **Hybrid aggregation** — host-side merge: take the deterministic pass/fail booleans, fold in the real-LLM cost numbers. The summariser still works.

A real `MarketplaceClient` exposes `scorecard(address)` as a thin shim over whichever store the host populates from the eval pipeline. The mock used here keeps an in-memory map keyed on `address.raw`; production hosts back it with whatever they back the rest of the marketplace index with.

## Graceful degradation

Both the review-state pill and the scorecard pill render iff the host wired them. Concretely:

- `client.reviewState?` not implemented → no review-state pill on any card.
- `client.scorecard?` not implemented → no scorecard pill on any card.
- A specific listing has no scorecard (i.e. `client.scorecard(address)` resolves to `undefined`) → that one card gets no scorecard pill; siblings render normally.

This matches the V-6.c "host-driven, opt-in" contract — the browser surfaces what the host hands it, never more.

## Standalone scorecard panel

The `<MarketplaceScorecardPanel>` is exported separately so hosts can drop it into a recipe-detail page without pulling in the browse list:

```tsx
import { MarketplaceScorecardPanel } from '@atelier/components';

<MarketplaceScorecardPanel scorecard={scorecards['atelier://acme/founder-inbox@1.0.0']} />;
```

Composition rule: `leaf`. Content is prop-driven; manifest authors do not embed children inside it.
