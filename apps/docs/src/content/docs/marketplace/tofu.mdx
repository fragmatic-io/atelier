---
title: Trust on first use (TOFU)
description: How consumers establish and maintain trust with bundle authors.
---

The marketplace's trust model is **trust on first use** — the first time a consumer fetches a bundle from `acme`, the client records the observed `key_id` fingerprint. Every subsequent fetch from `acme` must match.

This is the same model SSH uses for host keys. Imperfect (it doesn't establish trust on first contact — only stability after first contact), but battle-tested and pragmatic.

## The TOFU algorithm

```text
on fetch(address):
  bundle = GET /vault/marketplace/<author>/<persona>@<version>
  if !verify_signature(bundle): throw SignatureMismatchError
  if address.signed_by:
    if address.signed_by != bundle.key_id: throw MarketplaceTrustError
    return bundle.payload  // pinned — bypass TOFU cache
  known = trustedKeys.get(author)
  if known is undefined:
    trustedKeys.set(author, bundle.key_id)   // first contact
  elif known != bundle.key_id:
    throw MarketplaceTrustError(known, observed)
  return bundle.payload
```

## The reference client

`MarketplaceClient` in `@atelier/vault-client/src/marketplace.ts` implements this:

```ts
import { MarketplaceClient, InMemoryTrustedKeyStore } from '@atelier/vault-client';

const client = new MarketplaceClient({
  vaultUrl: 'https://vault.example',
  trustedKeys: new InMemoryTrustedKeyStore(),
});

try {
  const payload = await client.fetch(parseMarketplaceAddress('atelier://acme/email-triage@1.0.0'));
  console.log(payload.recipe);
} catch (err) {
  if (err instanceof MarketplaceTrustError) {
    console.error(`Trust mismatch: known=${err.knownKeyId} observed=${err.observedKeyId}`);
  }
}
```

## The `TrustedKeyStore` interface

```ts
export interface TrustedKeyStore {
  get(author: string): Promise<string | undefined>;
  set(author: string, keyId: string): Promise<void>;
  delete(author: string): Promise<void>;
  list(): Promise<Array<{ author: string; key_id: string }>>;
}
```

Two reference implementations ship:

- **`InMemoryTrustedKeyStore`** — Node-side default. Lost on process restart.
- **`LocalStorageTrustedKeyStore`** — browser default. Survives reloads. Per-origin.

Hosts that need persistence in Node — or stricter posture (e.g. fail closed on first use) — supply their own implementation.

## Pinning bypasses TOFU

When the address carries `?signed_by=<key_id>`:

```text
atelier://acme/email-triage@1.0.0?signed_by=8f3a2b1c4d5e6f70
```

The client checks `address.signed_by === bundle.key_id` and throws `MarketplaceTrustError` on mismatch. The TOFU cache is not consulted; not updated.

This is the high-stakes pattern: a consumer with strong opinions about which key they want signs the address with the explicit fingerprint. Useful for production deployments installing trusted recipe bundles.

## What happens on a key change

The author rotates their key. Their next bundle is signed with the new key:

```text
T+0:  consumer fetches v1.0.0 signed by key_A → trust_store.set('acme', 'key_A_fingerprint')
T+1:  consumer fetches v1.0.1 signed by key_B → MarketplaceTrustError(known='key_A_...', observed='key_B_...')
T+2:  user inspects both fingerprints out-of-band
T+3:  user calls client.trustedKeys.set('acme', 'key_B_fingerprint')
T+4:  consumer fetches v1.0.1 again → success
```

Today this is a CLI / API flow. Browser-side TOFU UI (a "key changed — accept or reject?" modal) is roadmap.

## Strict posture: fail closed on first use

For high-stakes hosts, override the TOFU cache to require explicit acknowledgment of every author:

```ts
import { TrustedKeyStore } from '@atelier/vault-client';

class StrictTrustedKeyStore implements TrustedKeyStore {
  private allowed: Map<string, string>;

  constructor(initial: Record<string, string>) {
    this.allowed = new Map(Object.entries(initial));
  }

  async get(author: string): Promise<string | undefined> {
    return this.allowed.get(author);
  }

  async set(): Promise<void> {
    throw new Error('Strict store rejects implicit trust. Pin via ?signed_by=...');
  }

  async delete(author: string): Promise<void> {
    this.allowed.delete(author);
  }

  async list() {
    return [...this.allowed.entries()].map(([author, key_id]) => ({ author, key_id }));
  }
}

const client = new MarketplaceClient({
  vaultUrl: 'https://vault.example',
  trustedKeys: new StrictTrustedKeyStore({
    acme: '8f3a2b1c4d5e6f70',
    taskmaster: '1234abcd5678ef90',
  }),
});
```

Only pre-allowlisted authors can be fetched; anything else fails. Recommended for production hosts pulling from a curated marketplace subset.

## Trust ≠ permission

Important: TOFU establishes that "this bundle came from the author I think it did." It does NOT grant capabilities. The user still walks through the consent surface (the vault's OAuth-style UI) to grant scoped access for whatever capabilities the recipe declares.

```text
1. Fetch bundle (TOFU verifies author identity)
2. Inspect bundle (recipe, capabilities, skills)
3. User grants scopes via vault consent UI
4. Recipe takes effect
```

## Errors

```ts
export class MarketplaceTrustError extends Error {
  constructor(
    public knownKeyId: string,
    public observedKeyId: string,
  ) {
    super(`Author key changed: known=${knownKeyId} observed=${observedKeyId}`);
  }
}
```

Carries both fingerprints so the host can render an informed decision surface.
