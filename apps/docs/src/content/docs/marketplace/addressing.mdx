The marketplace addressing scheme is `atelier://` — a custom URI shape designed to fit Atelier's specific distribution model (signed bundles, per-version immutability, optional fingerprint pinning).

## The grammar

```text
atelier://<author>/<persona>@<version>[?signed_by=<key_id>]
```

| Segment      | Shape                                       | Semantics                                                   |
| ------------ | ------------------------------------------- | ----------------------------------------------------------- |
| `<author>`   | `[a-z0-9][a-z0-9._-]{0,127}`                | The publishing vault account id.                            |
| `<persona>`  | `[a-z0-9][a-z0-9._-]{0,127}`                | The bundle name (recipe / persona / capability set).        |
| `<version>`  | semver 2.0.0                                | Exact match required at fetch time.                         |
| `?signed_by` | 16-char lowercase hex (sha256-truncated fp) | Optional explicit pin to a specific public-key fingerprint. |

## Examples

```text
atelier://acme/email-triage@1.0.0
atelier://taskmaster/founder-inbox@2.4.1
atelier://stripe/dashboard-defaults@0.1.0
atelier://hostagency/octant@1.0.0?signed_by=8f3a2b1c4d5e6f70
```

The `?signed_by=` pin form skips the TOFU cache; the fetch must match the pinned fingerprint exactly. Use it for high-stakes deployments where you want explicit-key-pinning rather than first-contact-trust.

## The reference parser

`@atelier/schemas/src/marketplace.ts` ships `parseMarketplaceAddress` and `formatMarketplaceAddress`. Both round-trip exactly:

```ts
import { parseMarketplaceAddress, formatMarketplaceAddress } from '@atelier/schemas';

const parsed = parseMarketplaceAddress('atelier://acme/email-triage@1.0.0');
//   parsed === {
//     scheme: 'atelier',
//     author: 'acme',
//     persona: 'email-triage',
//     version: '1.0.0',
//     signed_by: undefined,
//   }

const formatted = formatMarketplaceAddress(parsed);
//   formatted === 'atelier://acme/email-triage@1.0.0'
```

## Why a custom scheme

Three reasons we don't reuse `https://`:

1. **Per-version immutability is a contract.** `https://` URIs can change content silently. `atelier://` declares the version on the URI; the bundle is signed against that version; the resolver enforces match.
2. **Fingerprint pinning is first-class.** `?signed_by=<key_id>` is a standard query parameter; HTTP-flavoured URIs don't have a clean idiomatic place for this kind of trust-pin.
3. **Vault routing.** The address is parsed by the consumer's vault client, which decides which vault to fetch from based on the `<author>`. A future discovery surface might map `acme` → `https://vault.acme.example`; the URI shape stays stable.

## Author identifiers

The `<author>` segment is the publishing vault account id. In v0 there's no global registry — each vault server tracks its own authors locally. Cross-vault federation is roadmap.

A reasonable convention: `<author>` matches the publishing organisation's domain prefix (`acme`, `taskmaster`, `stripe`). Disambiguation across vaults happens via the `signed_by` fingerprint when ambiguity arises.

## Persona identifiers

The `<persona>` segment is bundle-author-defined. Common shapes:

- `email-triage`
- `founder-inbox`
- `octant-defaults`
- `marigold-checkout-v2`

These are case-sensitive lowercase. The validator rejects upper-case characters or whitespace.

## Version semantics

Strict semver 2.0.0. Pre-release tags (`1.0.0-beta.1`) and build metadata (`1.0.0+build.456`) are allowed but discouraged for marketplace distribution — consumers expect stable channels.

Republishing `acme/email-triage@1.0.0` overwrites the prior bundle (today). Per-version immutability is a follow-up; the recommended discipline is to bump to `1.0.1` for any change.

## Validation

Both `parseMarketplaceAddress` and the vault server's path validator reject:

- Mixed-case characters in author / persona.
- Whitespace anywhere.
- `..` or `/` in author / persona.
- Versions that don't pass `semver.valid()`.
- `signed_by` values not 16 lowercase hex chars.

A malformed address returns `400 { error: 'malformed marketplace address' }` from the server; the parser throws `MarketplaceAddressError` client-side.

## Code: pinning a fetch

```ts
import { MarketplaceClient, formatMarketplaceAddress } from '@atelier/vault-client';

const client = new MarketplaceClient({ vaultUrl: 'https://vault.example' });

// Pinned fetch — bypasses TOFU
const payload = await client.fetch(
  parseMarketplaceAddress('atelier://acme/email-triage@1.0.0?signed_by=8f3a2b1c4d5e6f70'),
);

// Unpinned fetch — uses TOFU cache
const payload2 = await client.fetch(parseMarketplaceAddress('atelier://acme/email-triage@1.0.0'));
```
