# Build-time agent execution

The production path is explicit, bounded and artifact-based. It does not silently claim specialist reasoning when running a deterministic preview.

1. A source snapshot is stored under tenant/project scope. A separate worker parses it with bounded extractors and the exact lockfile TypeScript compiler; no source code runs.
2. A deterministic authorized task plan chooses registered slot capabilities, fields and reviewed actions for the target role/permissions. This is a hard boundary the model cannot expand.
3. In Model mode, the architect proposes workflow/success criteria against the retrieved project facts.
4. The designer proposes focus/workbench/comparison structure and sections from the exact field/capability vocabulary. It can change grouping, hierarchy, copy and data presentation, but not invent authority.
5. An independent critic reviews task completeness and design coherence. One repair attempt is allowed. That attempt receives the rejected design, its hash, structured critique and unchanged required coverage. Deterministic field/action/schema checks run regardless of model opinion; cache reuse cannot replace the repair with the original rejected request.
6. The source forge emits token-resolved TSX/CSS/contracts/stories for an editable project kit, using permitted host primitive imports. Source syntax/AST restrictions run; arbitrary host typecheck or browser tests are not fabricated.
7. A structurally valid bundle becomes a draft. Human review is required; optional image critique stores model opinion and image hashes against the exact artifact. Production promotion has a separate review gate by default.

Each call passes through the same budget/cache/provenance gateway. Project model routing can use one provider for architecture and another for design/criticism. Visual critique requires an image-capable API; CLI adapters reject that request rather than hallucinating a screenshot review.

## Shared design and production source quality

The structured-surface and Source Forge lanes both resolve approved host design evidence into the versioned `DesignContext`. The designer and critic receive that exact context plus bounded authored task-pattern guidance. The compiler and exported host kit bind it to the source digest. Host primitive mappings must forward the marker, class and accessibility props described by the generated integration handoff.

Source Forge also fixes a caller-supplied quality contract before model work. The production profile requires independent scenario assertions and expected action inputs, browser/accessibility checks, retained captures, and critique of actual screenshots. Repairs reuse the same oracle and recompile/retest each candidate. A vision-provider failure remains a failure with retained non-approvable evidence. Human review is still required after automation passes.

Coding agents should read [PRODUCTION_UI.md](PRODUCTION_UI.md) before changing source-quality behavior and [RELEASE_EVIDENCE.md](RELEASE_EVIDENCE.md) before changing promotion. Use synthetic data in tests. Add a focused regression for changed behavior, then run `npm run test:unit`, `npm run verify`, and the committed-tree acceptance command in `AGENTS.md`. Report missing browsers, live credentials, deployment evidence and reviewer authority explicitly; do not replace them with fixtures or successful status strings.

Future native composition, progressive rendering and typed edits are specified in [INTELLIGENT_UI_PLAN.md](INTELLIGENT_UI_PLAN.md). They must preserve these same contracts and host authority boundaries.

The broader local V2 DAG/reuse/novelty utilities remain available in `packages/agents` and `packages/component-forge`. They are not represented as twenty independent live agents in the platform. New synthesis stages must have typed input/output, validation, cancellation, scope, budget, provenance and an explicit publication path.
